| 项目 | 内容 |
|---|---|
| 记录日期 | 2026-11-20 |
| 目标 | 本机 Windows 上 IDEA 运行的 `JetLinksApplication`，复用 192.168.56.130 上 Docker 容器内的 PostgreSQL / Redis |
| 改动文件（本机） | 新增 `jetlinks-standalone/src/main/resources/application-local.yml`（**不进仓库**，`.gitignore` 第 30 行已忽略） |
| 改动文件（服务器） | `/opt/jetlinks/docker/run-all/docker-compose.override.yml` 增加 5432 / 6379 端口映射（详见《部署改动记录.md》改动 6） |

## 一、链路拓扑

```
Windows 本机                          192.168.56.130 (CentOS 7)
┌───────────────────────┐             ┌──────────────────────────────────┐
│ IDEA 运行 JetLinks     │  TCP 5432   │ jetlinks-ce-postgres (5432→5432) │
│ Spring Boot :8848      │ ──────────► │   jetlinks_dev  (本地开发库)      │
│ profile: default,dev,local           │   jetlinks      (容器实例在用)    │
│                        │  TCP 6379   │ jetlinks-ce-redis   (6379→6379)  │
│                        │ ──────────► │   db1 (本地) / db0 (容器实例)     │
└───────────────────────┘             └──────────────────────────────────┘
```

> 本地实例**不依赖**容器里的 `jetlinks-ce`，可以在它继续运行的情况下独立启动（库、Redis 索引均已隔离）。

---

## 二、为什么要两个"隔离"

| 隔离项 | 做法 | 不隔离的后果 |
|---|---|---|
| 数据库 | 新建 `jetlinks_dev` | 两个实例同时连 `jetlinks` 同一套表：表结构版本冲突、设备在线状态互踢、时序数据混写 |
| Redis | 本地 `REDIS_DATABASE: 1` | 共用 db0：token 缓存、RPC 集群成员（server-id = `jetlinks-platform:8848`）互相覆盖，容器实例与本地实例互相"看见"却调不通 |

## 三、执行命令流水（本次实际操作，可复现）

### 1. 服务器：override 增加端口映射并生效

```yaml
# /opt/jetlinks/docker/run-all/docker-compose.override.yml（追加在对应服务下）
  postgres:
    ports:
      - "5432:5432"
  redis:
    ports:
      - "6379:6379"
```

```bash
cd /opt/jetlinks/docker/run-all
docker compose up -d
```

实测输出（postgres、redis 因端口参数变化被重建）：

```
 Container jetlinks-ce-redis  Waiting
 Container jetlinks-ce-postgres  Waiting
 Container jetlinks-ce-redis  Healthy
 Container jetlinks-ce-postgres  Healthy
 Container jetlinks-ce  Started
```

### 2. 服务器：防火墙与端口确认

```bash
systemctl is-active firewalld      # inactive → 无需 firewall-cmd 放行
ss -lntp | grep -E ':(5432|6379)'  # docker-proxy 已在 0.0.0.0 与 [::] 监听
docker compose ps                  # 0.0.0.0:5432->5432/tcp、0.0.0.0:6379->6379/tcp
```

### 3. 服务器：创建独立开发库

```bash
docker exec jetlinks-ce-postgres psql -U postgres -c 'CREATE DATABASE jetlinks_dev OWNER postgres'
docker exec jetlinks-ce-postgres psql -U postgres -d jetlinks_dev -c 'CREATE EXTENSION IF NOT EXISTS timescaledb'

# 校验
docker exec jetlinks-ce-postgres psql -U postgres -d jetlinks_dev -tAc 'select extname,extversion from pg_extension'
# plpgsql|1.0
# timescaledb|2.32.1
```

### 4. 服务器：远程凭据自检（确认容器内也能经宿主机 IP 连上）

```bash
docker exec -e PGPASSWORD='JetLinks@postgres' jetlinks-ce-postgres \
  psql -h 192.168.56.130 -p 5432 -U postgres -d jetlinks_dev -c 'select current_database()'
docker exec jetlinks-ce-redis redis-cli -a 'JetLinks@redis' -n 1 ping    # PONG
```

### 5. Windows：连通性验证

```powershell
Test-NetConnection 192.168.56.130 -Port 5432   # TcpTestSucceeded : True
Test-NetConnection 192.168.56.130 -Port 6379   # TcpTestSucceeded : True
```

### 6. Windows：新增本地配置文件

`jetlinks-standalone/src/main/resources/application-local.yml`（全文）：

```yaml
DB_HOST: 192.168.56.130
DB_PORT: 5432
DB_DATABASE: jetlinks_dev
DB_USERNAME: postgres
DB_PASSWORD: JetLinks@postgres
DB_SCHEMA: public

REDIS_HOST: 192.168.56.130
REDIS_PORT: 6379
REDIS_PASSWORD: JetLinks@redis
REDIS_DATABASE: 1

TIMESCALEDB_SCHEMA: public
TIMESCALEDB_FUNCTION_SCHEMA: public
ADMIN_USER_PASSWORD: JetLinks@admin
```

**为什么这样能生效**：`application-default.yml` 把连接参数定义成**普通顶层 key**（`DB_HOST:`、`REDIS_HOST:` …），
`application.yml` 里再通过 `${DB_HOST}` 等占位符引用。Spring 的 profile 文件按优先级叠加，
`local` 在 `default` 之后加载，因此同名 key 自动覆盖 —— 无需改动任何仓库文件。
`application-default.yml` 首行注释也明确要求本地开发这么做。

`ADMIN_USER_PASSWORD` 只在**空库首次建表**时写入管理员初始密码，因此本地开发库 `jetlinks_dev` 首次启动后：
账号 `admin` / 密码 `JetLinks@admin`。

## 四、在 IDEA 中启动

### 运行配置

`.run/JetLinksApplication.run.xml` 已有配置，关键项：

| 项 | 值 |
|---|---|
| 主类 | `org.jetlinks.community.standalone.JetLinksApplication` |
| module | `jetlinks-standalone` |
| VM 参数 | 一串 `--add-opens` + `-XX:+EnableDynamicAgentLoading`（不要删，Netty / Reactor 反射需要） |
| 环境变量 | `ACTIVE_PROFILES=default,dev,local`（**必须包含 `local`**，否则读不到 `application-local.yml`） |

操作：Docker 工具栏无需操作，直接点 `JetLinksApplication` 的 Run（或 Debug）。

### 启动时的正常现象

1. 日志出现 `The following 3 profiles are active: "default", "dev", "local"` —— 确认 profile 生效。
2. 首次启动会在 `jetlinks_dev` 中建表（`public` schema 产生 50 多张表）并装时序表，耗时 1~3 分钟。
3. `TimescaleDB` 相关日志无 `extension not found` 报错。
4. 监听 `:8848` 后访问 <http://127.0.0.1:8848> 用 `admin` / `JetLinks@admin` 登录。

### 注意

- **本地 8848 与服务器 8848 不冲突**（不同主机）。但不要在本机把 `EXTERNAL_HOST` 改成远程 IP，否则本地实例会以远程地址对外注册。
- 首次启动会在**工作目录**下生成 `./data/files`、`./data/logs`（`file.manager.storage-base-path`、`logging.file.name` 的默认相对路径），属正常产物，仓库 `.gitignore` 已忽略 `/data/`。
- 若 IDEA 之前把 `ACTIVE_PROFILES` 改过（例如只留 `dev`），需补回 `local`。

## 五、实测验证结果（2026-11-20 15:28–15:32，已跑通）

为避免只停留在"配置看起来对"，直接用 `jetlinks-standalone/target/application.jar`（当日 10:40 构建产物）在本机实跑了一次：

```powershell
$ java -Xms256m -Xmx1024m `
  --add-opens java.base/java.lang=ALL-UNNAMED --add-opens java.base/java.util=ALL-UNNAMED `
  --add-opens java.base/java.util.concurrent=ALL-UNNAMED --add-opens java.base/java.io=ALL-UNNAMED `
  --add-opens java.base/java.net=ALL-UNNAMED --add-opens java.base/java.text=ALL-UNNAMED `
  --add-opens java.base/java.math=ALL-UNNAMED --add-opens java.scripting/javax.script=ALL-UNNAMED `
  --add-opens java.base/java.time=ALL-UNNAMED -XX:+EnableDynamicAgentLoading `
  -jar .\jetlinks-standalone\target\application.jar `
  --spring.profiles.active=default,dev,local `
  "--spring.config.additional-location=file:./jetlinks-standalone/src/main/resources/"
```

（`spring.config.additional-location` 是为了让外置的 `application-local.yml` 被加载；IDEA 里不需要，它直接从源码资源目录读。）

| 检查项 | 实测结果 |
|---|---|
| profile | `The following 3 profiles are active: "default", "dev", "local"` |
| 启动耗时 | `Started JetLinksApplication in 49.489 seconds` |
| 本地 8848 | `GET http://127.0.0.1:8848` → **HTTP 200**，`Get-NetTCPConnection 8848` 监听正常 |
| 远程建表 | 远程 `jetlinks_dev` 的 `public` schema **56 张表**（TimescaleDB 时序表已建） |
| Redis 隔离 | `SELECT` 实测：db1（本地实例）1 个 key，db0（容器实例）12 个 key，**互不干扰** |
| 管理员登录 | `POST /authorize/login`（`admin` / `JetLinks@admin`）→ 返回 32 位 token，`expires: 1800000`，说明 `ADMIN_USER_PASSWORD` 在空库首启时已生效 |
| 容器实例未受影响 | 验证期间 `192.168.56.130:8848` 一直在跑，未重启、未报错 |

验证结束后已停掉该进程，8848 端口释放，可直接在 IDEA 里启动。

> 首次实跑曾因命令行 `--add-opens` 不全失败：`Unable to make field ... java.math.BigDecimal.intVal accessible`（`clusterManager` 创建失败）。
> 原因是 Redis 序列化用到 Jackson 反射 `BigDecimal`。**IDEA 运行配置里的 9 个 `--add-opens` 一个都不能少**，用源码在 IDEA 启动时配置已齐全，无需处理。

## 七、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动报 `Unable to connect to Redis` | `REDIS_PASSWORD` 缺失或 `REDIS_DATABASE` 未设；`spring.cache.type: redis` 下 Redis 不通必然启动失败 | 核对 `application-local.yml` 中三行 Redis 配置 |
| 启动报 `relation "xxx" does not exist` | 连到了 `jetlinks` 而非 `jetlinks_dev`，或 profile 未含 `local` | 检查日志里的 r2dbc url 与 profile |
| 报表已存在 / 两端数据串 | 未做库隔离 | 回到第三章第 3 步独立建库 |
| 端口 5432/6379 超时 | override 未生效（未在 `/opt/jetlinks/docker/run-all` 目录执行）或 firewalld 被开启 | `docker compose ps` 看端口，`systemctl is-active firewalld` |
| 密码含 `@` 导致 URL 解析失败 | `r2dbc:postgresql://user:JetLinks@postgres@host` 中 `@` 会被当分隔符 | 走 yml 的 `password` 字段（本文做法）即可；若必须写在 URL 里需转义为 `%40` |

> 备注：容器内 PostgreSQL 已设 `POSTGRES_HOST_AUTH_METHOD=trust`，当前**任何密码都能连**，`DB_PASSWORD` 的实际值不起校验作用；
> Redis 则是真校验（`requirepass JetLinks@redis`）。该 trust 配置使 5432 对整个网段免密开放，详见《部署改动记录.md》风险表。

## 八、回滚

```bash
# 服务器：收回端口（本地开发不再需要时）
# 编辑 docker-compose.override.yml 删除 postgres/redis 的 ports，然后：
cd /opt/jetlinks/docker/run-all && docker compose up -d

# 删除开发库（确认本地无需要保留的数据）
docker exec jetlinks-ce-postgres psql -U postgres -c 'DROP DATABASE jetlinks_dev'
```

本机：删除 `jetlinks-standalone/src/main/resources/application-local.yml` 即回到 127.0.0.1 默认值（该文件不受 git 管理，删除无副作用）。
