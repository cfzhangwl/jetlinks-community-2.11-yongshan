### 步骤 5：故障定位

```bash
# 1) 看日志
docker logs jetlinks-ce-postgres | tail -30
```

关键输出：

```
creating configuration files ... ok
LOG:   could not write to file "postmaster.pid": Operation not permitted
FATAL: could not write to file "pg_wal/xlogtemp.36": Operation not permitted
initdb: removing contents of data directory "/var/lib/postgresql/data"
```

```bash
# 2) 查权限与文件系统
ls -ld /opt/jetlinks/docker/run-all/data/postgres     # drwx------ 2 70 root
getenforce                                            # Disabled（SELinux 不是原因）
findmnt -T /opt/jetlinks                              # xfs, rw，不是只读
```

```bash
# 3) 用同镜像以 uid 70 向该目录写文件 —— 成功
docker run --rm -u 70:70 -v /opt/jetlinks/docker/run-all/data/postgres:/x \
  timescale/timescaledb:latest-pg16 bash -c 'cd /x; echo test > t.txt && echo WRITE_OK'
# 输出：WRITE_OK
```

→ 结论：**不是权限问题，普通写入可以，只有 PG 初始化时的写入被拦截**。

```bash
# 4) 换挂载方式对照：bind 到 /tmp、命名卷，两种都复现同样报错
docker run --rm -u 70:70 -v /tmp/pgtest:/data timescale/timescaledb:latest-pg16 initdb -D /data
docker run --rm -v pgtest_vol:/data ... bash -c 'chown -R 70:70 /data && su-exec postgres initdb -D /data'
# 两者均报 could not write to file "postmaster.pid": Operation not permitted
```

→ 结论：**与挂载方式无关，是运行环境层面的问题**。

```bash
# 5) 安全策略对照：放开 seccomp / privileged
docker run --rm -u 70:70 --security-opt seccomp=unconfined -v /tmp/pg2:/data \
  timescale/timescaledb:latest-pg16 initdb -D /data     # 成功
docker run --rm -u 70:70 --privileged -v /tmp/pg3:/data \
  timescale/timescaledb:latest-pg16 initdb -D /data     # 成功
```

→ 结论：**根因是 Docker 默认 seccomp 策略在这台 3.10 内核上拦截了 PG 的写入系统调用**。
`privileged` 与 `seccomp=unconfined` 都能解决，选择后者（影响面更小，只放开 seccomp）。

### 步骤 6：写入 override 修正配置

```bash
cat > /opt/jetlinks/docker/run-all/docker-compose.override.yml <<'EOF'
services:
  jetlinks:
    environment:
      JAVA_OPTS: "-Duser.language=zh -Xms512m -Xmx1536m -XX:MaxMetaspaceSize=256m"
  postgres:
    security_opt:
      - seccomp=unconfined
EOF
```

校验（只读，不启动容器）：

```bash
cd /opt/jetlinks/docker/run-all && docker compose config | grep -E 'security_opt|seccomp|JAVA_OPTS:'
```

结果：

```
JAVA_OPTS: -Duser.language=zh -Xms512m -Xmx1536m -XX:MaxMetaspaceSize=256m
security_opt:
  - seccomp=unconfined
```

### 步骤 10：宿主重启后的恢复与加固（13:14 重启事件）

13:17 复检时发现三个容器全部消失，`docker ps -a` 显示：

```
jetlinks-ce          | Exited (255) 3 minutes ago
jetlinks-ce-postgres | Exited (255) 3 minutes ago
jetlinks-ce-redis    | Exited (255) 3 minutes ago
uptime: up 3 min，系统引导 2026-11-20 13:14
```

原因：目标机在 13:14 重启，`docker` 服务本身为 `is-enabled enabled`（会自启），
但三个容器 `RestartPolicy.Name=no`，重启后不会自动拉起。

处理 1 —— 先按原配置恢复：

```bash
cd /opt/jetlinks/docker/run-all && docker compose up -d
```

约 30 秒后 `http://127.0.0.1:8848/` 返回 200，容器状态：

```
jetlinks-ce          | Up 39 seconds
jetlinks-ce-postgres | Up 51 seconds (healthy)
jetlinks-ce-redis    | Up 51 seconds (healthy)
```

数据库侧核对（说明后端真正初始化完成，而非仅端口监听）：

```bash
docker exec jetlinks-ce-postgres psql -U postgres -d jetlinks -tAc "select count(*) from information_schema.tables where table_schema = 'public'"
# 56

docker exec jetlinks-ce-postgres psql -U postgres -d jetlinks -tAc "select extname, extversion from pg_extension"
# plpgsql|1.0
# timescaledb|2.32.1
```

业务表已生成（`dev_device_instance`、`dev_product`、`alarm_record`、`access_logger` 等）。

处理 2 —— 补 `restart: always` 到 override（见《部署改动记录.md》改动 3），然后：

```bash
cd /opt/jetlinks/docker/run-all
docker compose config | grep -E 'restart:|seccomp|JAVA_OPTS:'   # 校验三处 restart
docker compose up -d                                              # 重建容器使策略生效
docker inspect -f "{{.Name}} restart={{.HostConfig.RestartPolicy.Name}}" \
  jetlinks-ce jetlinks-ce-postgres jetlinks-ce-redis
```

结果：

```
/jetlinks-ce          restart=always
/jetlinks-ce-postgres restart=always
/jetlinks-ce-redis    restart=always
```

重建后再次验证：8848 第 3 次探测（约 18 秒）返回 200，三容器 Up，内存占用
`jetlinks-ce 748.7 MiB`、`postgres 99.1 MiB`、`redis 7.1 MiB`。

### 步骤 11：把 restart 策略写进仓库 compose 文件（13:21）

上一轮的 `restart: always` 只落在服务器侧 override，无法版本化。本轮改为写进仓库文件本身：

```bash
# 本机：编辑 docker/run-all/docker-compose.yml，三个服务的 container_name 下一行各加 restart: always
# 校验换行符保持 LF（CRLF=0）
git diff --stat
#  docker/run-all/docker-compose.yml | 9 ++++++---
#  1 file changed, 6 insertions(+), 3 deletions(-)

# 同步到目标机
scp docker-compose.yml root@192.168.56.130:/opt/jetlinks/docker/run-all/docker-compose.yml

# 同时清理 override 中重复的 restart 字段（避免两处定义）
# 校验合并结果
cd /opt/jetlinks/docker/run-all && docker compose config | grep -E 'restart:|seccomp|JAVA_OPTS:'
#    JAVA_OPTS: -Duser.language=zh -Xms512m -Xmx1536m -XX:MaxMetaspaceSize=256m
#  restart: always      ← jetlinks
#  restart: always      ← redis
#    - seccomp=unconfined
#  restart: always      ← postgres

# 应用（合并结果与上一轮一致，容器未重建，保持 Running）
docker compose up -d
```

验证：

```bash
docker inspect -f '{{.Name}} restart={{.HostConfig.RestartPolicy.Name}}' jetlinks-ce jetlinks-ce-postgres jetlinks-ce-redis
# /jetlinks-ce restart=always
# /jetlinks-ce-postgres restart=always
# /jetlinks-ce-redis restart=always

curl -s -o /dev/null -w 'HTTP %{http_code}\n' http://127.0.0.1:8848/   # HTTP 200
```

Windows 侧 `Invoke-WebRequest http://192.168.56.130:8848/`：`HTTP 200`。

## 四、复现步骤（从零到可用）

```bash
# 1. 准备镜像（若已有本地构建镜像，先补标签）
docker tag <IMAGE_ID> jetlinks-community-2.11:latest

# 2. 准备目录与配置
mkdir -p /opt/jetlinks/docker/run-all/data
cp docker-compose.yml /opt/jetlinks/docker/run-all/
# 按《部署改动记录.md》改动 3 创建 docker-compose.override.yml

# 3. 拉依赖
docker pull redis:6
docker pull timescale/timescaledb:latest-pg16

# 4. 启动
cd /opt/jetlinks/docker/run-all && docker compose up -d

# 5. 验证
docker compose ps
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8848/
```

> 若在 4.x 以上内核的主机上部署，可先去掉 override 中的 `security_opt: seccomp=unconfined` 再试；
> 只有出现 `could not write to file "postmaster.pid": Operation not permitted` 时才需要该项。
