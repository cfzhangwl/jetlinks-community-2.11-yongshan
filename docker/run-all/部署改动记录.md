### 改动 3：新建 `docker-compose.override.yml`（唯一实质性配置改动）

- **位置**：`/opt/jetlinks/docker/run-all/docker-compose.override.yml`
- **改动前**：不存在
- **改动后**：完整内容（逐字）

```yaml
# 本地环境覆盖层：不修改仓库中的 docker-compose.yml
# restart 策略已写入仓库 docker-compose.yml（三个服务均 restart: always），此处不再重复
services:
  jetlinks:
    environment:
      # 显式固定 JVM 堆，避免按宿主机内存比例自动推断（默认 25%）
      JAVA_OPTS: "-Duser.language=zh -Xms512m -Xmx1536m -XX:MaxMetaspaceSize=256m"
  postgres:
    # 宿主机内核为 3.10（CentOS 7），Docker 默认 seccomp 会拦截 PG 的写入调用，
    # 导致 initdb 报 "could not write to file postmaster.pid: Operation not permitted"
    # 仅对 postgres 放行 seccomp，其余服务保持默认
    security_opt:
      - seccomp=unconfined
```

**生效机制**：Compose 在同一目录执行时自动叠加 `docker-compose.yml` + `docker-compose.override.yml`，等价于
`docker compose -f docker-compose.yml -f docker-compose.override.yml`。
合并规则：标量字段后者覆盖前者；`environment` 按 key 合并，同 key 用后者；`ports` / `volumes` 为追加。

**改了两处**（override 内）：

| 服务 | 字段 | 原值（docker-compose.yml） | 新值（override） |
|---|---|---|---|
| jetlinks | `JAVA_OPTS`（第 46 行） | `-Duser.language=zh` | `-Duser.language=zh -Xms512m -Xmx1536m -XX:MaxMetaspaceSize=256m` |
| postgres | `security_opt` | 无（走默认 seccomp） | `seccomp=unconfined` |

> `restart: always` 已于 2026-11-20 13:21 直接写入仓库 `docker-compose.yml`（见改动 5），因此不再在 override 中重复。

**JVM 参数含义**：

- `-Xms512m`：初始堆，避免启动阶段反复扩堆
- `-Xmx1536m`：最大堆。`docker-entrypoint.sh` 只写了 `java $JAVA_OPTS`，未指定堆，JVM 默认按物理内存 25% 推断（约 1.9 GB），显式固定后行为可预测，也给 PostgreSQL / Redis / 系统留余量
- `-XX:MaxMetaspaceSize=256m`：元空间上限，防止无界增长

**postgres seccomp 放行的背景**（详见《部署执行记录.md》排查章节）：
按仓库原始配置启动时，`jetlinks-ce-postgres` 首次初始化即失败：

```
LOG:  could not write to file "postmaster.pid": Operation not permitted
FATAL: could not write to file "pg_wal/xlogtemp.36": Operation not permitted
```

经对照测试确认：数据目录权限正常（uid 70 可正常写入）、bind 挂载与命名卷均复现、SELinux 已关闭、
加 `--security-opt seccomp=unconfined` 后 initdb 立即成功 → **根因是 Docker 默认 seccomp 策略在 3.10 内核上拦截了 PG 的写入调用**。
因此只对 postgres 一个容器放开 seccomp，`redis`、`jetlinks` 仍走默认策略。

**restart 策略的背景**：2026-11-20 13:14 目标机重启后，三个容器全部变为 `Exited (255)` 且未自动拉起
（宿主机 `docker` 服务本身为 `systemctl is-enabled enabled`，问题只在于容器没有重启策略）。
该策略最终写入仓库 `docker-compose.yml`，见改动 5。

**校验方式（只读，不启动容器）**：

```bash
cd /opt/jetlinks/docker/run-all
docker compose config | grep -E 'restart:|security_opt|seccomp|JAVA_OPTS:'
```

实测输出包含 `restart: always`（三处，来自 docker-compose.yml）、`seccomp=unconfined` 与 `JAVA_OPTS: -Duser.language=zh -Xms512m -Xmx1536m -XX:MaxMetaspaceSize=256m`。

- **回滚**：`rm /opt/jetlinks/docker/run-all/docker-compose.override.yml`，compose 完全回到仓库原始配置；注意回滚后 postgres 在该内核上无法初始化，本机应保留该文件。

### 改动 5：仓库 `docker-compose.yml` 增加 `restart: always`（三个服务）

- **位置**：仓库文件 `docker/run-all/docker-compose.yml`（**唯一被修改的仓库原文件**），并同步到 `/opt/jetlinks/docker/run-all/`
- **改动前**：三个服务均无 `restart` 字段（默认 `no`）
- **改动后**：每个服务的 `container_name` 下一行增加 `restart: always`

```yaml
    redis:
        image: redis:6
        container_name: jetlinks-ce-redis
        restart: always          # 新增（第 6 行）

    postgres:
        container_name: jetlinks-ce-postgres
        restart: always          # 新增（第 22 行）

    jetlinks:
        image: jetlinks-community-2.11:latest
        container_name: jetlinks-ce
        restart: always          # 新增（第 40 行）
```

共 3 处插入，`git diff --stat` 显示 `6 insertions(+), 3 deletions(-)`（删改来自被替换的三行上下文，实际新增 3 行）。
文件换行符保持 LF（`CRLF=0`），未引入 Windows 风格换行。

- **原因**：13:14 宿主重启后三容器全部 `Exited (255)`，容器本身没有重启策略，宿主机 `docker` 服务虽已开机自启也拉不起来。写进仓库文件，配置可版本化、换机器部署即自带该策略。
- **生效方式**：`docker compose up -d` 不需要重建即可保留已有容器的策略（本次合并结果与 override 版本一致，容器未重建）；新机器首次 `up -d` 时直接生效。
- **校验**：

```bash
docker inspect -f '{{.Name}} restart={{.HostConfig.RestartPolicy.Name}}' jetlinks-ce jetlinks-ce-postgres jetlinks-ce-redis
# /jetlinks-ce restart=always
# /jetlinks-ce-postgres restart=always
# /jetlinks-ce-redis restart=always
```

- **回滚**：删除上述 3 行即可；或在仓库执行 `git checkout -- docker/run-all/docker-compose.yml`。

## 四、已知风险（未改动，仅记录）

| 风险 | 说明 | 建议 |
|---|---|---|
| postgres `seccomp=unconfined` | 该容器不再受默认 seccomp 约束，隔离性下降；是本机 3.10 内核下的必要妥协 | 生产环境建议升级到 Docker 支持的较新内核，去掉此项 |
